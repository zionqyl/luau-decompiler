# Controlled normal-engine native test place

The prepared [controlled-place.rbxlx](../fixtures/roblox-v3/controlled-place.rbxlx)
contains **14 distinct known-source programs**: 11 ModuleScripts, two LocalScripts,
and one Script with RunContext explicitly set to Client (serialized value 2).
The two LocalScripts and client Script are disabled to avoid automatic execution.
The [manifest](../fixtures/roblox-v3/manifest.json) pins every source hash, instance
class, storage/runtime path, probe and required input. It plans 42 behavioral
observations, not 42 distinct native programs. Timing repetitions and supplied
bytecode fixtures are separate counters and are zero in this procedure.

**Normal-engine compilation and the controlled native-client run were not run.**
There was no connected Roblox Studio/test-place publishing environment. A
connected executor in an unrelated public game does not provide this controlled
environment. The prepared file was XML-validated, regenerated byte-identically,
and all 14 sources compiled using the pinned official 0.746 host compiler.
Those checks do not establish that Roblox imported, compiled or replicated the
instances. [Actual preparation evidence](evidence.md).

## Program identities and probes

| Program | Class | Exercised behavior |
| --- | --- | --- |
| ScalarBinary | ModuleScript | Exact binary strings, nils, numeric results and ordered print effects |
| CaptureCounter | ModuleScript | Three stateful calls of the same returned closure per input |
| LoopMutation | ModuleScript | Numeric/generic loops, break, table mutation and aliasing |
| ProtectedCalls | ModuleScript | Nested protected calls, exact error bytes, multiple returns and a valid scheduler yield |
| OwnedMethods | ModuleScript | Only an unparented owned Folder; attributes, methods and destruction |
| VectorValues | ModuleScript | Vector3 construction, cross product, components and raw f32 vector observations |
| ModuleInterface | ModuleScript | Exported callbacks, shared state, snapshot fields and fresh table identity |
| ModuleDependency | ModuleScript | Known static module interface |
| RequireDependency | ModuleScript | `require` of the package's own sibling dependency |
| LargeFunction | ModuleScript | 1,024 generated arithmetic updates |
| LargeModule | ModuleScript | 128 exported functions, each consumed by the unchanged trusted probe |
| LocalBinary | LocalScript | Client-visible LocalScript getter and binary warn events |
| LocalLoop | LocalScript | Client-visible LocalScript getter and repeat loop |
| ClientMethods | Client Script | RunContext Client getter; only an owned unparented Part and Vector3 values |

The source scripts are small enough to review. The generator creates the two
large shapes deterministically. The runner accesses only these exact identities
under `DecompilerV3Fixtures`; it does not discover or execute unrelated game code.

## Reproduction

1. Run from the repository root:

   ```powershell
   ./scripts/build-native-place.ps1
   ./scripts/verify-native-fixtures.ps1
   ```

2. Open the generated `.rbxlx` in Roblox Studio. Check the 14 classes/paths and
   source hashes before publishing to a **private test place you control**. Keep
   scripts disabled and record the published PlaceId, place version and package
   hash. Changes to a source require rebuilding the marker/manifest and publishing
   a new test version. The marker is operator-controlled publication evidence,
   not cryptographic attestation of inaccessible native Source text.

3. Start a client in that place and connect the explicitly chosen executor. The
   runner requires the documented script bytecode getter and a native script
   closure getter. It also needs `loadstring`, `getfenv`, `setfenv`, scheduler
   support and executor HTTP. An absent client-visible script, unsupported getter,
   unknown container or unsupported bytecode feature is recorded as an unsuccessful
   or not-run case; there is no fallback to executor-compiling its source and
   calling that native extraction.

4. Start the authenticated Rust loopback service and load the adapter/runner using
   the executor's documented local-file facility. Supply the token in memory:

   ```lua
   local Adapter = assert(loadstring(readfile("adapter/decompile.luau")))()
   local NativeTest = assert(loadstring(readfile("adapter/native-test-v3.luau")))()
   local HttpService = game:GetService("HttpService")
   local manifest = HttpService:JSONDecode(readfile("fixtures/roblox-v3/manifest.json"))
   local report = NativeTest.run(Adapter, manifest, {
       expected_place_id = 123456789, -- replace with the controlled published PlaceId
       architecture = "x86_64", -- record actual host/process evidence separately
       adapter_options = {
           token = "the service token",
           endpoint = "http://127.0.0.1:7879/v1/decompile",
           executor_profile = "madium",
           bytecode_encoding = "roblox_opcode227", -- processed Madium contract only
           timeout = 15,
           reconstruction_config = {
               vector_constructor = "Vector3.new", -- explicit trusted environment contract
               validation = { mode = "check" },
               closures = { entry_invocation = "repeated", compiler_closure_sharing = false },
           },
       },
   })
   writefile("native-v3-report.json", HttpService:JSONEncode(report))
   ```

   Select another executor's documented profile/getters/representation explicitly.
   Do not guess encoding by trying decoders until one accepts the input. The above
   Madium settings are not a claim of other-executor compatibility. `setfenv`
   instrumentation is itself a required test capability, not a required capability
   for ordinary Rust decompilation.

   The runner always requests repeated-entry semantics. `DUPCLOSURE` arrangements
   whose cross-entry identity cannot be faithfully represented are rejected.
   Enable `compiler_closure_sharing` only with evidence that the chosen executor's
   recompilation preserves the required closure-sharing behavior, record that
   contract, and still check every identity observation. Do not switch to the
   single-entry mode merely to turn an unsupported repeated-entry case into a pass.

5. Transfer the complete report without string truncation, then run:

   ```powershell
   cargo build --release --offline --example oracle_compare
   ./scripts/verify-native-report.ps1 -Capture native-v3-report.json
   ```

   The verifier requires every pinned identity and all three inputs, parses each
   typed LOBS frame using Rust, checks binary framing and retains failed cases.
   Native bytecode and source hashes, exact executor/runtime, platform and stated
   architecture belong in the compatibility matrix. Retain the published place
   metadata and service binary hash alongside the capture.

## Observation boundary

Each original entry and reconstructed entry is loaded once and reused across the
three inputs. The runner tracks whether returned functions reuse identity across
those entry calls. Stateful and module probes invoke the same loaded callbacks
repeatedly and preserve complete return tuples, including nils. Print/warn effects,
raw errors, vector bits and buffer snapshots use typed length-delimited frames.
Unsupported values make a probe incomplete even if script `pcall` catches the
observer error. Pure conformance tests include eight collision negatives and three
incomplete observations.

The instrumentation environment is reused for each entry sequence: changing its
identity on every call could invalidate Luau's environment-sensitive closure cache
and conceal a reconstruction bug. The entry environment and adapter state are
restored. The runner never calls an executor's built-in decompiler.

The probes establish only the listed operations and inputs. Roblox diagnostics,
native userdata atom callbacks, source-location-sensitive errors and executor
representation restrictions can still prevent complete reconstruction. They must
remain failures. The scheduler-yield case needs a genuine client scheduler; an
offline compiler pass does not test yielding. A non-yielding faulty reconstruction
may require the engine's execution timeout or restarting the disposable private
test client; this harness does not claim preemptive VM isolation.

Windows/macOS/mobile statuses remain separate. This fixture package does not
provide a tested macOS binary or an authenticated encrypted phone companion.
A phone's loopback cannot reach the PC service. Do not change the service to a
public listener or call an unencrypted network URL to manufacture mobile evidence.
