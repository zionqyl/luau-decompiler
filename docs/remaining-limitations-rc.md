# Candidate limitations and untested environments

This is the supported boundary for `0.4.0-rc.4`. Final release readiness depends on the frozen-source gate and packaged acceptance, not on a claim of universal compatibility or an issue-free implementation. The [support matrix](support-matrix-rc.md), [input contract](source-input.md), [output policies](output-policies.md), and [validation procedure](validation.md) give the detailed interfaces.

| Area | Boundary |
| --- | --- |
| Input formats | Explicit Luau version profiles 3 through 14 and evidenced raw/signed representations are supported within implemented semantic scope. Marker-based auto-detection never verifies cryptographic authenticity; unmarked opcode227 needs an explicit getter contract. Standard Lua/LuaJIT bytecode is recognized and rejected. Source remains a documented UTF-8 subset. |
| Source syntax and dialects | Interpolated strings, user-defined type functions, generic defaults, type-metatable and newer class/declaration forms remain unsupported. The Lua path is a Lua 5.1 compatible syntax intersection with explicit library/environment assumptions. Its observations run in the pinned Luau VM; an independent Lua 5.1 runtime equivalence campaign has not run. |
| Source presentation | Runtime tokens, useful names and valid original types are retained through a separate Rust source path. Additional inference covers immutable primitive expressions, bounded closed return packs and justified scalar callbacks; mutable structural postconditions and open packs remain conservative. Formatting preserves supported structure but is not a complete general-purpose Luau formatter. Explanatory comments are removed; functional directives, literal data and required notices are preserved. |
| Instructions and constants | Native userdata callbacks, unproved prototype guards, 64-bit integer constants, experimental classes and runtime-patched operations retain explicit diagnostics. The whole retained corpus decodes, but reconstruction still rejects unsupported structural/semantic cases and resource deadlines. Format or opcode presence is not behavioral evidence. |
| Control flow | Dispatcher/native-loop combinations require implemented entry/exit proofs. Some nested generic searches with nonlocal loop exits remain unsupported; child diagnostics retain their prototype/PC and never trigger a parent fallback panic. Unproved capture, branch, open-result and insertion histories reject explicitly. |
| Tables | Fresh ordered record fills and contiguous reserved array fills have narrow reconstruction proofs. Escaped, reordered, conditional, aliased, self-capturing or otherwise unproved histories remain unfolded or unsupported as appropriate. The unconstrained 512-function benchmark retains a nil-prefilled array that the strict analyzer narrows to nil elements before callback writes; this is a known engine output/type-state defect, with the exact diagnostic families recorded in [performance evidence](performance-rc.md). Exact template/key layouts are validated; arbitrary physical table histories are not universally reconstructible. |
| Types and aliasing | Calls lack a general read-only effect proof. Reachable aliases, captures and opaque table-return relationships therefore invalidate facts conservatively and may reduce annotations even for benign code. Unknown dependencies, mutable interfaces, recursion budgets and lost metadata can prevent verified typing. Original erased aliases, generic spelling and precise interfaces cannot be recovered exactly. |
| External contracts | Player and project/module contracts are explicit assumptions. Names and one successful runtime input do not establish a class or entire interface. Arithmetic alone does not exclude metamethod behavior or justify narrowing an unknown callback parameter to number. The separately contracted 512-function fixture tests its declared interface; it does not make the default module's table-state defect a missing-context error. Missing DataModel/project context remains visible. |
| Verified typing | Final parser/compiler/strict and meaningful-typing requirements are enforced separately from behavioral checks. Explicit/inferred dynamic types, unmeasured contracts, type-budget exhaustion and unsupported assumptions can fail the gate. Passing strict analysis does not prove runtime equivalence. |
| Recovery | Only implemented finite strategies run under shared deadlines, cancellation, work and memory accounting. Optional typing/presentation can roll back. No arbitrary guards, conversions, defaults, swallowed errors, casts or changed return lists are inserted to clear diagnostics. |
| Function entries and captures | Function mode emits a chunk returning the serialized fixed/variadic entry. Live upvalue values are not contained in ordinary serialized bytecode. A detected nil-placeholder executor capture wrapper rejects; the conservative rule also rejects legitimate function factories with that exact shape in function-entry mode. Other unproved capture representations remain unsupported. |
| Closure lifetime | Default scope covers one loaded root invocation and repeatable returned closures under its reported contracts. Repeated-root mode supports only its separately verified subset; captured-cache rejection cases remain required negatives. Debug-local/stack introspection and arbitrary environment mutation are outside the general equivalence contract. |
| Native integration | Rc.4 completed one unknown-source Madium LocalScript getter/adapter/HTTP round trip with the final binary; syntax/compilation passed but strict/meaningful typing failed. Rc.2 separately retains five known-source function programs, 21 exact comparisons and one absent-capture rejection. Normal-engine known-source scripts and the full current target matrix remain untested. Native HTTP cancellation handles remain unavailable. Historical failed transport is separate. |
| Linux and remote hosting | Clean Ubuntu 24.04 CI passed native build/MSRV/lint/ordinary checks, extracted-runtime typed acceptance and direct container startup, verified request, same-container restart and clean shutdown. [Exact evidence](hosting.md#evidence-boundary-for-this-candidate) applies to its recorded commit/environment. Detailed artifacts require authenticated retrieval. Published image access, distinct-image upgrade/rollback, bootstrap lifecycle and reverse-proxy HTTPS remain unverified. Other Linux distributions are not certified. |
| Other platforms | No Mac runner is available; macOS packages/tests are not run. Android/iOS same-device or authenticated encrypted companion executor integration is not certified. A mobile loopback address cannot reach a PC service. |
| Resources | Persistent pools, bounded queues, cancellation and response leases bound admitted work. Weighted memory accounting is not a hard RSS/heap quota. Native APIs without cancellation handles may outlive an adapter timeout. Process-tree memory must be measured separately from parent working set; sustained-run results cover their actual duration and load only. |
| Performance and provenance | Comparisons are mixed and apply to their recorded executables/settings. Archived pre-correction results are historical. Validation-off timing is not verified-typed performance. Shared-host scheduling, small tail samples and allocation-observer overhead limit comparisons. Final reports and examples identify their source, configuration and executable. |

Original source locations, stack layout, VM-added error prefixes, allocation/GC timing, OOM behavior, compiler closure-sharing details and source spelling are not universally preserved. The typed oracle compares its declared observations exactly; unsupported or incomplete observations never become behavioral success.

See [candidate assessment](release-candidate.md) for what actually completed and [performance evidence](performance.md) for measurement boundaries. Historical [v0.3 limits](remaining-limitations-v3.md) describe that release and include problems subsequently repaired; they are not the active candidate contract.

Windows extracted-package and PATH-isolated checks are distinct from a fresh operating-system VM. Complete clean Windows acceptance remains pending. A separate clean Ubuntu 24.04 GitHub runner completed the Linux boundary; the local Windows development host still has no Linux/Docker runtime. Neither result establishes macOS, mobile or cross-distribution compatibility.

Browser assets require a WASM-capable browser and workers. Only recorded browser runs establish support. Browser memory accounting combines explicit input/output limits and worker supervision with separate Rust/C++ linear-memory caps; it is not a browser-process RSS quota. Custom supplemental definition files are not exposed in this candidate; pinned definitions, virtual source modules and supported explicit contracts are available. Offline browser reuse is not advertised. See [browser limits](browser.md) and [client snapshot and authorized MM2 showcase](client-corpus.md).
