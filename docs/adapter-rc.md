# Optional executor adapter contracts

The adapter is a client of the standalone core, not a dependency of local, library or self-hosted processing. It installs an explicitly selected native profile or a generic canonical helper and can restore the predecessor even when installations are removed out of order. Extraction, native options, representation selection, authentication and transport remain outside the reconstruction core.

The default encoding is now `auto`, matching native and browser processing. It recognizes only the [supported structural representations](bytecode-representations.md). Unmarked opcode227 still requires an established getter contract and explicit setting. Older services that do not advertise `auto` require an explicit supported encoding; the handshake never silently substitutes one. Historical rc.2 live evidence verifies its archived adapter and observer bytes, not the current source.

`decompile(target, nativeOptions)` follows the selected documented profile. Custom timeouts are configured in `Adapter.install` or `decompile_with_timeout`; the native second argument is not reinterpreted as a numeric timeout. Raw strings bypass script getters. Function targets require a real advertised function getter and request `entry_output="function"`. Function entry source represents the dumped function rather than executing it as a zero-argument script. External live upvalue values remain unavailable unless independently supplied by a supported contract; dispatch mocks do not verify real function dumps.

Native option normalization first validates a finite acyclic JSON-compatible option graph: fewer than 12 nested table levels, at most 8192 entries across the entire graph, keys at most 256 bytes, and at most 2 MiB of key/value string data. Both native and canonical paths reject cycles, excessive depth, unsupported values and duplicate aliases. Shared acyclic tables are permitted within the aggregate traversal budget. Formatter/DecompilerOptions traversal is deterministic; nested wrappers do not recurse before validation.

`cancel_on_timeout` controls cancellation sent for elapsed adapter deadlines. `cancel_on_restore` independently controls cancellation sent when restoring the installation. Disabling timeout cancellation therefore does not suppress restoration cancellation. Local request state is invalidated in either case. A native HTTP API without a cancellation handle can continue running after local timeout; in-flight admission remains held until its callback actually returns.

Source-returning helpers enforce the selected output policy. Verified-typed output requires the actual service report to show passed syntax, compilation, strict analysis, meaningful typing and the required policy gate. Missing report fields fail this policy. HTTP 422 quality results preserve faithful output and diagnostics: detailed helpers return the full result with `http_status=422`; source-only helpers raise a structured quality error retaining source, baseline and validation. Transport/extraction errors retain their existing documented propagation boundary.

Remote endpoints require `allow_remote=true` and HTTPS. Numeric HTTP loopback remains the easy default. The service requires `--allow-remote` when it binds beyond loopback; the [self-hosting configuration](hosting.md) supplies authentication and a TLS reverse proxy. Implemented remote configuration, native getter availability and catalog presence are separate from a live successful compatibility test.

The candidate boundary suite is [adapter/test-rc.luau](../adapter/test-rc.luau). It covers cyclic/deep/wide option graphs, alias conflicts, unsupported values, all four timeout/restoration cancellation combinations, verified-policy rejection and positive mocks, retained HTTP 422 reports, function-entry dispatch and remote URL restrictions. These are injected API tests, **not** live executor evidence. Existing [adapter tests](../adapter/test.luau) and [v0.3 tests](../adapter/test-v3.luau) remain required. Fresh live results must identify the exact final executable, adapter, real getter packet, platform/executor build, configuration and controlled known-source program.

Independent controlled compiler/VM observations cover the latter semantics. No controlled known-source normal-engine script fixture was available in this session; historical function-dump evidence remains separate.
