# Reproducible larger corpus

`generate.ps1` creates ten deterministic Luau scripts and their pinned `-O2 -g2` bytecode in `artifacts/benchmark-corpus`. Sources use a dynamic `local seed = ... or 1` and deterministic arithmetic constants. No random, time, environment, or network globals are used. The input remains dynamic during compilation, so whole-script constant folding cannot erase the measured work.

| Inputs | Source scale | Analysis pressure |
| --- | --- | --- |
| `linear_512`, `linear_1024` | 512 or 1024 sequential arithmetic updates | Many definitions in a small CFG; decoder, expression reconstruction, formatting, allocations |
| `branches_64`, `branches_128` | 64 or 128 sequential `if/else` diamonds | Roughly three blocks per check plus entry/exit, joins, dominators and reaching definitions |
| `functions_64`, `functions_128` | 64 or 128 escaping functions plus main | Independent function analysis with a shared parent capture; prototype and closure overhead |
| `loops_16`, `loops_32` | 16 or 32 separate nested numeric-loop pairs | Multiple loop regions, loop-carried values, and reused lexical names |
| `closures_16`, `closures_32` | 16 or 32 three-level closure factories | Mutable reference captures shared between a child and grandchild; closure dependency preservation |

These scales are generator parameters, not claims about exact optimized opcode counts. The manifest records source/bytecode byte counts and SHA-256 hashes; the decompiler's per-script statistics report actual prototypes and instructions. Both the generated source and bytecode are retained for inspection. Generation uses UTF-8 without a BOM and LF newlines; compiler stdout is captured as bytes. The default Windows compiler is checked against `upstream.lock.json`. A build from the same pinned source can use `-AllowCustomCompiler`; the manifest records its actual hash and `verified_release_compiler: false`.

Run from the repository root:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
. ./scripts/env.ps1
./benchmarks/generate.ps1
./benchmarks/validate.ps1
$benchmarkInputs = @(Get-ChildItem artifacts/benchmark-corpus -Filter '*.bc' | Sort-Object Name | ForEach-Object { $_.FullName })
./scripts/benchmark.ps1 -Inputs $benchmarkInputs -Threads @(1, 2, 4, 8) -Iterations 100 -Destination artifacts/benchmarks-large
```

`validate.ps1` compares original and decompiled execution at one deterministic seed (default 7), checking numeric results, escaping function results, mutable capture state and fresh closure identity. It retains every input in the denominator and writes `oracle-report.json`. Pass `-Decompiler target/debug/luau-decompile.exe` for a debug build. This focused oracle complements the full optimization/debug regression matrix; it is not a correctness proof.

Use the same manifest and configuration for comparisons. The root benchmark script starts a separate release process at each thread count and measures peak working set in that process. The CLI reports complete per-script latency, wall throughput, source hashes, and corpus hashes; loading files and creating the worker pool are excluded. Output hashing is included in wall throughput and excluded from individual latency. It checks source determinism across iterations and thread counts in a single benchmark invocation. Cross-process reports should be compared by their `output_sha256` arrays as well.

For a single larger script, `luau-decompile decompile INPUT --threads 4` uses an explicitly bounded pool for independent function analysis. The single-script default is one thread, with a maximum of 64; batch processing retains its separate script-level worker setting. Closure assembly and source ordering remain deterministic. Compare single-script output at `--threads 1` and `--threads 4` when measuring this mode; the batch benchmark command measures script-level concurrency.

The corpus is synthetic and deliberately includes larger shapes than the semantic regression cases. Report its results separately from those regression fixtures. It is useful for identifying allocation and scaling regressions; it does not establish real-world Roblox workload performance or semantic coverage. Unsupported cases must be reported as errors, never removed from a reported denominator. Measured results belong in the generated benchmark reports; this file makes no unmeasured performance claims.

## Large scale and many-input corpus

The generate-scale.ps1 script separately generates a pinned modern format-14
corpus:

| Scenario | Default source scale | Generated bytecode size in this run |
| --- | --- | --- |
| One large function | 4,096 dynamic arithmetic updates; 4,099 source lines | 117,973 bytes |
| One large module | 512 exported functions × 24 dynamic updates; 14,338 source lines | 381,325 bytes |
| Many independent scripts | 2,000 distinct arithmetic, branch, closure and loop programs | 619,865 bytes combined |

These 2,002 inputs total 1,119,163 bytecode bytes in the recorded generation.
The generator checks the exact official compiler hash and records every source
and bytecode SHA-256, exact compiler flags, version, counts and parameters in
artifacts/scale-corpus/manifest.json. Sources use runtime arguments so whole
program constant folding cannot erase the measured work. A separate trusted
probe for the module consumes its exported functions and returns scalar results.
Generation records complete_behavioral_validation as false; compilation and
hashes establish provenance, not behavioral success.

The separate large_scale_behavior test currently verifies both large programs
against original compiled bytecode at seeds -3/0/1/7: **8/8 complete typed
comparisons**. It recompiles the known source and requires exact equality with
the stored fixture before comparing behavior. The 512-function module uses
unchanged separate probe bytecode to invoke every exported operation. Its
[report](../docs/evidence.md) explicitly excludes the 2,000 small
inputs; a complete reconstruction/throughput run of those inputs is a separate
measurement.

~~~powershell
. ./scripts/env.ps1
./benchmarks/generate-scale.ps1
cargo test --offline --test scale_behavior large_scale_behavior -- --ignored --nocapture
foreach ($threads in @(1,2,4,8)) {
    ./target/release/luau-decompile.exe benchmark --manifest artifacts/scale-corpus/paths-many_independent_inputs.json --threads $threads --iterations 10 -o ("artifacts/scale-"+$threads+".json") --force
}
~~~

The generated paths-all, paths-many_independent_inputs, paths-one_large_function
and paths-one_large_module JSON arrays avoid Windows command-line length limits.
The example records warm core timing; use the isolated process peak-memory
measurement workflow for memory, and retain separate reports for each scenario.

Pass -Version 6 for a separate legacy corpus, and retain each manifest.
The Inputs, FunctionUpdates and ModuleFunctions parameters configure bounded
scales. Report large-function, large-module, 2,000-script warm core, streaming
batch and adapter/service measurements separately. Do not classify an
unsupported input, incomplete observation or failed reconstruction as a
benchmark success.
